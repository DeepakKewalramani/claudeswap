Why ClaudeSwap

Built for developers who run multiple Claude accounts

When one account hits its limit, the workflow should keep moving. ClaudeSwap is the layer between you and the manual login dance.

Instant switching

Add each Claude account once. When you hit a limit, handoff resumes the exact conversation under another profile in under two seconds.

Zero credential handling

ClaudeSwap never reads, stores, intercepts, or logs tokens, cookies, passwords, or keychain secrets. Authentication stays native inside each profile.

Quota telemetry

Watch live token use, cost, and status per profile in one place, so the next account choice is informed, not a guess.

Session explorer

Every past session grouped by workspace, with token gauges and execution trails. Reopen any session in one keypress.

Supervisor matrix

A live matrix of up to 20+ background sessions across repositories. Attach, fork, kill, or check status in one place.

Shared memory

Transcripts, project memory, and edit history pool across profiles when you turn context on. Handoffs keep the thread.

          Security architecture
          
    An environment coordinator, never an auth agent
    
          
    ClaudeSwap points Claude Code at an isolated folder with CLAUDE_CONFIG_DIR. Login, tokens and keychain stay inside Claude Code. It runs fully local and sends nothing to external servers.
    
        
    
        
    
          
    
            Who owns what

    ClaudeSwap
  profile registry    ~/.claudeswap/profiles.json
  isolated dirs       ~/.claudeswap/profiles/<id>/
  shortcuts           ~/.claudeswap/bin/
  shared context      ~/.claudeswap/shared/
        |
        | injects CLAUDE_CONFIG_DIR
        v
Claude Code
  native OAuth handshake and token storage
  local secrets (.claude.json)
  LLM interaction and agent tools
    
          
    
          
    
            Filesystem layout

    ~/.claudeswap/
  config.json         # mode 0600
  profiles.json       # mode 0600
  shared/             # unified context pool
    sessions/  projects/  file-history/  plans/
    history.jsonl
  profiles/           # CLAUDE_CONFIG_DIR targets
    work/  personal/
  bin/                # generated shortcuts
  backups/            # atomic .bak copies
    
          
    
        
    
        
      
          
    1. Zero credential touch. It never parses, opens or logs OAuth tokens, cookies or secrets. Switching is done only through CLAUDE_CONFIG_DIR.
      2. 
          
    2. Zip-slip and path traversal immunity. chat import validates canonical paths and rejects .., absolute paths and escapes from the target folder.
      3. 
          
    3. No shell injection. claude is started with a direct argv slice, never through bash -c or sh -c.
      4. 
          
    4. Race-free concurrency. Shared memory, session scanning and supervisor state are thread-safe and tested with go test -race ./....
      5. 
          
    5. Atomic storage with self-healing. Metadata is written to a temp file and renamed, with an automatic .bak restore on corruption.
      6. 
          
    6. Strict permissions. Folders are 0700 and config files 0600, readable only by the current OS user.

          FAQ
          
    Frequently asked questions
    
          
    Short answers about switching accounts, limits, memory and security.
    
        
    
        
    
          
    
            How do I switch between multiple Claude Code accounts?
            
    Install ClaudeSwap, add each profile with claudeswap add <name>, then switch instantly with claudeswap handoff <name>. No logging out or re-authenticating.
    
          
    
          
    
            Can ClaudeSwap help when I hit a Claude rate limit or quota?
            
    Yes. When Claude Code reports a rate limit, run claudeswap handoff <other-account> to resume the exact same conversation under another account in under two seconds.
    
          
    
          
    
              Which account does a handoff go to when I have several?
              
    You choose. claudeswap handoff consulting goes to exactly that profile. Run claudeswap handoff with no name and a picker lists your other profiles with a status (Ready, Session out or Logged out). Nothing picks the next account for you.
    
            
    
          
    
            Does ClaudeSwap store my Claude API keys or tokens?
            
    No. ClaudeSwap never reads, stores, intercepts, or logs tokens, OAuth cookies, passwords, or keychain secrets. Authentication stays 100% native inside each Claude Code profile.
    
          
    
          
    
            Does context carry over when I switch accounts?
            
    With claudeswap context on, shared memory pools transferable project context, transcripts, and file edit history across profiles without sharing credentials.
    
          
    
          
    
            Can I run multiple Claude Code sessions at once?
            
    Yes. The claudeswap matrix command supervises 20+ parallel background sessions across repositories with live status, token use, and one-click attach or fork.
    
          
    
          
    
              How do I avoid daemon.lock conflicts with multiple sessions?
              
    Fork the session instead of attaching to a locked one: claudeswap sessions resume <session-id> --fork. In the sessions or matrix screens, press f to auto-branch with Claude Code's --fork-session flag.
    
            
    
          
    
              How does ClaudeSwap isolate profiles under the hood?
              
    Claude Code reads the CLAUDE_CONFIG_DIR environment variable. ClaudeSwap gives each profile its own folder (~/.claudeswap/profiles/<id>) with separate login, settings and cache, so profiles can also run in separate terminals at the same time.
    
            
    
          
    
            How do I install ClaudeSwap?
            
    On macOS and Linux run: curl -fsSL https://raw.githubusercontent.com/DeepakKewalramani/claudeswap/main/install.sh | sh. Or install with Go: go install github.com/DeepakKewalramani/claudeswap/cmd/claudeswap@latest.
